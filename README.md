# Construct Validity of Automated Evaluation Frameworks for RAG Systems

This repository contains the code and data for the bachelor's thesis *Construct validity of automated evaluation frameworks for RAG systems* (Leipzig University, 2026). We examine whether Ragas, TruLens and DeepEval measure what their metrics claim to measure. All three frameworks rate the same answers from one RAG system, and their scores are compared along the constructs of the RAG triad (faithfulness, context relevance, answer relevance).

| | Research question | Data |
|---|---|---|
| RQ1 | How do established RAG evaluation frameworks operationalize the constructs of the RAG triad, and in which respects do their operationalizations differ? | framework source code and publications |
| RQ2 | To what extent do the metrics of different frameworks converge when they claim to measure the same construct? | CRAG, RAGBench |
| RQ3 | To what extent do metrics that claim to measure different constructs remain empirically distinguishable? | same scores as RQ2, arranged as an MTMM matrix |
| RQ4 | To what extent can automated evaluation metrics serve as a proxy for whether a RAG system solves its task? | dependency validation dataset (Simon et al., 2024) |

## Repository structure

```
config/config.yaml   all parameters of the experiments 
src/rag_eval/        package: RAG pipeline, framework adapters, data loaders, analysis
scripts/             numbered steps of the experiments
data/processed/      answers generated by the RAG system 
results/scores/      raw framework scores, one line per sample, framework and construct
results/rq2|rq3|rq4/ analysis outputs
results/Auswertung_gesamt.xlsx   all analysis outputs in one workbook
```

## Setup

All runs used Python 3.12 on macOS (Intel). The versions are pinned to torch 2.2.2, the last release with wheels for Intel Macs.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.lock.txt
cp .env.example .env
```

API keys are only needed for steps that call a language model (see below).

## Reproducing the analyses

All analyses run on the included scores and do not call any language model.

```bash
# RQ2 and RQ3
python scripts/04_rq2_convergence.py --datasets crag ragbench --top-k 10
python scripts/04_rq2_convergence.py --datasets crag ragbench --top-k 5
python scripts/04_rq2_convergence.py --datasets ragbench_own
python scripts/06_rq3_discriminant.py --datasets crag ragbench --top-k 10
python scripts/06_rq3_discriminant.py --datasets crag ragbench --top-k 5
python scripts/06_rq3_discriminant.py --datasets ragbench_own
python scripts/09_trace_plausibilitaet.py      # downloads RAGBench from HuggingFace
python scripts/10_judge_diagonale.py
python scripts/12_manipulation_auswerten.py
python scripts/13_faithfulness_robustheit.py

# RQ4: the dataset is not included, it is rebuilt from the original repository
git clone https://github.com/simisimon/dependency-validation-rag.git data/raw/dependency-validation-rag
python scripts/02b_import_depvalidation.py
python scripts/08_rq4_criterion.py

python scripts/11_gesamt_excel.py
```

The outputs overwrite the files in `results/rq2`, `results/rq3` and `results/rq4`. They reproduce the included files exactly. The Excel files differ only in their creation timestamp.

## Running the full pipeline

Steps 01 and 02 require the raw datasets (downloaded via HuggingFace, see `config/config.yaml`) and a generator endpoint. Answers were generated with `google/gemma-4-26B-A4B-it` via SCADS.AI. Step 03 and scripts 14 and 15 call the judge (`gpt-4o-mini`) and incur API costs. Paid runs are logged locally in `results/usage.jsonl`, which is not included.

```bash
python scripts/01_build_index.py
python scripts/02_generate_answers.py
python scripts/03_run_frameworks.py
```

The manipulation conditions, the imported datasets and other judges are scored separately, for example `python scripts/03_run_frameworks.py --dataset crag_inject_1` or `--judge-model <model> --judge-endpoint generator`.

## File names

Every parameter that varies between runs is part of the file name, so that runs cannot overwrite each other:

```
data/processed/{dataset}_generated_{scope}_k{top_k}.jsonl
results/scores/{dataset}_{framework}_{scope}_k{top_k}_{judge}.jsonl
```

Imported datasets and manipulation conditions do not go through retrieval and carry neither scope nor top_k (e.g. `depvalidation_ragas_gpt-4o-mini.jsonl`). The naming is implemented in `src/rag_eval/naming.py`.
